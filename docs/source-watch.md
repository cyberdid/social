# Щоденна перевірка публічних джерел

`src/source_watch_collect.py` формує чергу ручної перевірки доступних сторінок і новинних посилань. Він не визначає правовий статус людини, достовірність заяви, винуватість чи завершення провадження. Нова HTTP-відповідь або зміна HTML не дорівнює новині.

## Що перевіряємо

```bash
cd /home/cyberdid/Projects/Social
/usr/bin/python3 src/source_watch_collect.py --dry-run
```

Останню залишено в плані попри зафіксовану TLS-помилку: недоступність не доводить відсутності документа. Додано два відомі репортажі про Валерію Ладику — Суспільне (`1446145`) та hromadske (`273906`), тексти й заголовки яких могли оновлюватися. Неуспішні старі орфографічні варіанти URL не дублюються. Інші домени та матеріал Суспільного про 18-річного підозрюваного до цього вузького плану не входять.

Чотири стрічки обрано як офіційні поверхні виявлення нових публікацій:

| НГУ | [Офіційна головна](https://ngu.gov.ua/) | Містить заголовки актуальних новин та пагінацію. Використовується домен `ngu.gov.ua`; схожий `ngu.com.ua` до плану не належить. |

План обмежений першою доступною сторінкою кожної стрічки. Пагінацію, JavaScript API, пошук, рекурсивні переходи та нові знайдені статті колектор автоматично не завантажує. Між щоденними запусками матеріал може пройти через першу сторінку й бути пропущений. Це не гарантія повноти офіційних оновлень.

## Запуск і результат

Залежності — уже використовувані в проєкті `requests` та `beautifulsoup4`. Ручний запуск:

```bash
cd /home/cyberdid/Projects/Social
/usr/bin/python3 src/source_watch_collect.py --timeout 20 --pause 1
```

Між адресами пауза одна секунда. На адресу встановлено бюджет 20 секунд, connect timeout до 5 секунд, read timeout до 10 секунд, до чотирьох redirect-переходів; бюджет додатково перевіряється між переходами та блоками отримання. Окреме блокувальне читання може завершитися після загального бюджету в межах read timeout. Ліміт отриманої розпакованої відповіді — 2 000 000 байтів. Обрізана відповідь має помилку `body_size_limit` і не порівнюється як стаття. Повторних спроб у тому самому запуску немає.

Використовується HTTPS із перевіркою TLS. Session не читає `.netrc`, змінні автентифікації/проксі чи зовнішні перевизначення CA (`trust_env=False`). Cookies перед кожним запитом очищаються. Немає логіну, секретів, платних сервісів, надсилання повідомлень чи обходу challenge. Redirect дозволений лише всередині того самого вихідного домену з фіксованого списку; сторонній або приватний redirect стає помилкою для ручного перегляду.

Кожен мережевий запуск створює нову директорію UTC:

```text
data/raw/source_watch/<YYYYMMDDTHHMMSS.microsecondsZ>/
  <url-hash>.html
  manifest.json
```

Директорії та raw-файли створюються виключно через `exist_ok=False`, `open('x')` / `open('xb')`. Попередні знімки читаються, але не перезаписуються. Маніфест завершує знімок: директорії без придатного маніфесту не стають базою порівняння.

Кожний рядок маніфесту містить вихідний URL, `status` (або `null` при мережевій помилці), `final_url`, час запиту, timeout, SHA256 та розмір отриманих байтів, локальний файл, помилку й відфільтрований вміст. Для запиту без отриманої відповіді SHA256 дорівнює `null`. З response headers зберігаються тільки `Content-Type`, `ETag`, `Last-Modified`; cookie-заголовки не зберігаються. SHA256 скрипта фіксується при імпорті модуля **до мережі**, а не перечитується після завершення запитів; `script_hash_captured=module_import_before_network` фіксує це правило. Ранні технічні знімки без цього маркера не підтверджують версію виконаного коду.

Оновлювані агрегати:

- `reports/source-watch/latest.json` — рядки та лічильники черги.
- `reports/source-watch/latest.md` — читабельний перелік станів і нових доступних посилань.

Тільки ці похідні звіти атомарно замінюються. Рядки `unchanged` залишаються у звіті для перевірки покриття. Помилки попереднього запуску не стирають успішну базову версію: новий вміст порівнюється з останнім успішним отриманням того самого URL серед усіх raw-маніфестів.

## Що означає зміна

Для статей відбираються відомі контейнери основного тексту (`.news-details`, `.l-article__content`, `article.post-body`, `article`, `main` та інші), додається основний заголовок, якщо він поза контейнером. Скрипти, стилі, форми, навігація, sidebar, footer, блоки поширення, приховані блоки джерел та рекомендації вилучаються. Поточна версія extractor — 2. Це евристика, а не гарантоване виділення редакційного тексту.

Для стрічок fingerprint складається зі стабільно відсортованих доступних новинних URL та підписів; tracking-параметри й fragments відкидаються. Для МВС/ДБР допускаються `/news/<slug>`, для Омбудсмана — `/news_details/<slug>`, для НГУ — посилання новин у заголовках. Таким чином календар, nonce, analytics і звичайна зміна HTML не створюють самі по собі повідомлення про новину.

| `event` | Значення |
|---|---|
| `new_page` | Перше успішне отримання сторінки. Це базова версія, а не доказ нової публікації. |
| `new_baseline` | Версія extractor відрізняється від попередньої. Часову зміну вмісту не обчислюємо; починаємо нову базову версію. |
| `filtered_change` | Змінився відфільтрований текст або перелік/підписи новинних посилань. Потрібен ручний перегляд. |
| `possible_change` | Не вдалося надійно виділити статтю/стрічку, але змінилися raw-байти, або змінився тип виділення. Можлива суто технічна зміна. |
| `unchanged` | Придатний fingerprint збігається; це не гарантує відсутності змін поза доступним текстом. |
| `error` | HTTP-помилка, TLS/network/timeout, challenge, непідтримуваний тип чи перевищений розмір. Це не факт відсутності новин або судового рішення. |

`extractor_version` зберігається поруч із fingerprint; при зміні його правил версію слід підвищувати. Маніфест без версії також починає новий baseline. У першому знімку всі відомі посилання стрічки є базовими; `new_news_links` заповнюється тільки відносно попереднього успішного знімка з тією самою версією extractor. Нове доступне посилання може вести до давнішого матеріалу, який щойно підняли у стрічці. Збіги «Борщагівка / Петропавлівська / Ладика» лише позначають пріоритет ручного перегляду й не доводять релевантності.

## Тести і відтворення без мережі

```bash
/usr/bin/python3 -m unittest discover -s tests -p test_source_watch_collect.py
/usr/bin/python3 src/source_watch_collect.py --rebuild data/raw/source_watch/<UTC>/manifest.json
```

Одинадцять offline-тестів перевіряють: відокремлення динамічної оболонки, прихованих джерел і рекомендацій від статті; матеріальну зміну тексту та заголовка; стабільні новинні посилання; fallback без автоматичного висновку; HTTP/TLS/challenge errors; правильні виправлені адреси; dry-run без мережі та створення raw; незмінність попередніх snapshot, SHA256, порівняння з останнім успіхом після помилки та побайтове відтворення агрегату; ліміти відповіді й timeout; заборону сторонніх/private redirect і credential-bearing URL; новий baseline при іншій версії extractor. Деякі тести перевіряють кілька пов'язаних інваріантів.

`--rebuild` перевіряє SHA256 кожного збереженого body і відтворює `latest.*` з записаних у маніфесті результатів порівняння, не завантажуючи й не змінюючи raw. Воно не повторює історичний HTTP-запит і не стверджує, що сторінка зараз така сама. Зміна генератора звіту може змінити вигляд Markdown; вихідні байти й fingerprint залишаються у знімку. Для незалежного тестового виводу можна передати `--raw-root` та `--report-dir`.
