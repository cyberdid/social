# Primary-source comparison of adjacent systems and investigation guidance

Checked 2026-11-10. This is a functional positioning review of primary publications and official documentation. It is not a head-to-head benchmark, an exhaustive review, a claim that another system lacks undocumented features, or an assessment of current service availability. The 2014/2016 papers and the historically framed plugin pages describe particular versions; their platform access must not be projected unchanged into 2026. Companion bibliography: `manuscript/references_systems.bib` (eight entries).

## Functional comparison and defensible boundaries

| Reference / unit | Supported capabilities in the inspected primary source | Scope and comparison boundary | Relevance to Social, without performance ranking |
|---|---|---|---|
| **GDELT Event Database v2.0**, official codebook dated 2015-02-19; key `gdelt2015events` | Dyadic CAMEO actor/action records, geographic estimates, event attributes and a separate Mentions table linking news mentions to events. Mentions carry extraction confidence and article-position indicators. | Event dates remain daily even though updates occur every 15 minutes; update time is not event-occurrence time. The codebook describes extracted news-event records, not adjudicated facts. See Introduction and EventID/Date attributes, pp. 1–2. [Official codebook](https://data.gdeltproject.org/documentation/GDELT-Event_Codebook-V2.0.pdf). | Precedent for separating event records from observations/mentions. Social should explain its own claim/passages/status model; this source supplies no empirical comparison with Social. |
| **GDELT GKG v2.1**, official codebook dated 2015-02-19; key `gdelt2015gkg` | Document-level codified entities, themes, locations, emotional/content measures, and links to relevant imagery/video/social embeds in news; multilingual processing. | The codebook describes a rich tab-delimited metadata format requiring preprocessing. Embedded social URLs do not by themselves demonstrate direct collection of every social platform or verified video semantics. See Introduction and new capabilities, pp. 1–2. [Official GKG codebook](https://data.gdeltproject.org/documentation/GDELT-Global_Knowledge_Graph_Codebook-V2.1.pdf). | Relevant to contextual metadata and cross-media discovery. Its automated content measures should not be conflated with passage-supported factual verification. |
| **ACLED**, living official codebook; key `acledCodebook` | Researcher-coded reported political violence, demonstrations and selected politically important nonviolent developments. Event records include actors, day, location, source, narrative notes, and date/geographic precision. | Scope is a defined political-disorder taxonomy. Actor order does not necessarily designate aggressor/victim. The codebook records no fatality information as zero reported fatalities; users must respect that convention. It leaves broader conflict/campaign aggregation to users. See Introduction, column table, and ACLED events. [Official codebook](https://acleddata.com/methodology/acled-codebook). | Strong precedent for explicit event units, uncertainty/precision fields, source coding and human review. It should be described as an adjacent event-data methodology, not a claim-verification software competitor. |
| **Event Registry (2014)**; key `leban2014eventregistry` | Groups news articles about the same event, including across languages; extracts event location/date/entities/topic; stores events; offers search, aggregation, visualization, individual article inspection and related-event exploration. | The described syntactic/semantic pipeline processes English, German, Spanish and Chinese. Article clustering is evidence organization; this review does not infer independent corroboration or adjudicated truth from cluster membership. The 2014 architecture is not a description of today's commercial service. See abstract and architecture, pp. 107–108. [Official conference paper](https://archives.iw3c2.org/www2014/proceedings/companion/p107.pdf). | Direct related work for news-to-event organization. Social's positioning should focus on its inspected integration and explicit evidence states, not claim novelty for event extraction or clustering. |
| **Hoaxy (2016)**; key `shao2016hoaxy` | Collects monitored misinformation/fact-checking website content and public Twitter URL-sharing observations; combines crawlers/RSS, streaming API tracking and database storage; studies aggregate sharing dynamics. | The authors explicitly state that the system does not perform fact checking: source accuracy is determined independently. The paper focuses on implemented monitoring; interactive dashboard analysis is described as planned. The source/domain lists and Twitter access define its observed sample. See Sections 2–3 and 4.1. [Author preprint](https://arxiv.org/html/1603.01511), [official proceedings PDF](https://archives.iw3c2.org/www2016/WWW2016-Proceedings/companion/p745.pdf). | Precedent for separating diffusion measurement from factual accuracy. Do not rebrand all monitored URLs as false individual claims or import the paper's aggregate temporal finding as a universal law. |
| **InVID verification plugin**, official project documentation; key `invidVerificationPlugin` | Journalist-facing video/image assistance: contextual video information, keyframe extraction, reverse-image search, metadata inspection, magnification and image forensic filters. | A verification toolbox supports analyst investigation; the official page does not establish automatic truthful-event reconstruction. Some external analysis/keyframe services are explicitly not open source. Listed platform integrations and release history are historical documentation, not verified current access. [Official plugin documentation](https://www.invid-project.eu/tools-and-services/invid-verification-plugin/). | Relevant prior work for human-assisted media inspection. Local video decoding/ASR in Social and forensic/context verification are different operations; technical decode should not be presented as comparable semantic verification. |
| **InVID–WeVerify verification plugin**, official redesigned-plugin page; key `weverifyVerificationPlugin` | The documented 2021 redesign adds OCR, fact-check search, cross-network search, image context, Twitter network analysis and assistant-guided tools; includes known-fakes similarity lookup and forensic functions. | Some advanced tools require registration and are reserved for defined user groups. The page describes services contributed by partners; it is not evidence every service is locally reproducible or currently reachable. Avoid presenting the 2021 page's usage statistics as current. [Official page](https://weverify.eu/verification-plugin/). | Relevant to an analyst's guided combination of tools. Do not claim Social is the first integrated verification workbench, or that a local code path alone provides equivalent end-to-end capability. |
| **Berkeley Protocol (2022)**; key `berkeleyProtocol2022` | Professional guidance for digital open-source investigations: planning, security, collection, preservation, verification, analysis and reporting, with templates and tool-validation considerations. | A methodological/legal/ethical protocol, not an executable platform or performance benchmark. Citing it does not establish compliance, evidentiary admissibility or valid implementation. Verification and preservation are distinct processes. See contents and investigation-process sections, printed pp. 53–72; tool-validation annex p. 87. [Official co-publisher PDF](https://humanrights.berkeley.edu/wp-content/uploads/archive/2024/02/Berkeley-Protocol.pdf), [UN publication record](https://digitallibrary.un.org/record/3973652?v=pdf). | Useful normative frame for capture documentation, preserved originals, explicit reasoning, limitations and human responsibility. Social's paper should identify implemented practices and remaining gaps rather than claim certification. |

The “comparison boundary” interpretations above are methodological inferences from what each inspected source describes, not experimentally demonstrated omissions. In particular, neither article multiplicity nor repeated platform posts necessarily create independent sources. The relevant comparison axes are unit of observation, source acquisition, event/claim representation, provenance, access/uncertainty reporting, analyst intervention, and what has actually been validated.

## Retrieval and comparison limits

Only primary documents and official project/tool pages support the table. Search results were used for discovery, then the official GDELT PDFs, ACLED codebook, WWW conference PDFs, Hoaxy author preprint, InVID/WeVerify pages, Berkeley co-publisher PDF and UN catalog were inspected. No external system was installed, executed, given account access, or tested on the Social incident corpus. Consequently no speed, coverage, accuracy, reliability, cost, or superiority claim is warranted.

For manuscript language, “adjacent systems address news-event organization, diffusion observatories, human-assisted media verification, and investigation procedure” is supported. “No prior system integrates these functions,” “Social outperforms these systems,” “automated fact-checking is solved,” and “Berkeley-compliant” are not established by this review.
