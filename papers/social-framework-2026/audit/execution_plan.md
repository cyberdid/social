# Social system-paper execution plan

User specification: full AUDIT → RESEARCH → EVALUATION → WRITING → FIGURES → LaTeX → PDF → REVIEW cycle. The publication describes the existing system; no base-code or previous case-paper edits.

1. Record Git state and perform a code-first audit of acquisition, normalization, evidence/event engines, media, audience, attribution, reporting and QA. Distinguish implementation, structural tests and empirical validation.
2. Reconcile the case-corpus and verification-version discrepancies. Build a claim/evidence matrix with file/function locations, input hashes, denominators and limits.
3. Finalize RQs and contributions from audited capabilities. Verify primary literature and position against related systems without comparative performance claims.
4. Reproduce bounded offline checks and record commands, environments, timing and output hashes. No new platform crawl or model inference expenditure is required for the baseline audit. Report unmeasured metrics explicitly.
5. Draft a separate complete English system paper, approximately 18–25 pages where evidence supports the length, with case application around 15–20% of main-text words.
6. Produce vector architecture/provenance/workflow/media and evaluation figures, six verified summary tables, and privacy-preserving figure data.
7. Build with bundled CMU fonts and verified author/declaration metadata. Inspect every rendered page and validate cross-references and bibliography.
8. Conduct distinct AI methodology, architecture/evidence and editorial reviews; fix critical/major issues; record remaining limits without claiming independent human review.
9. Deliver PDF in the main project root, editable LaTeX/BibTeX, audits, figure data and manifests. Commit/push the publication in the current branch; do not merge or publish externally.
