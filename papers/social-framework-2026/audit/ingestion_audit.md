# Ingestion, normalization, contracts, and provenance audit

Audit date: 2026-11-10. Code baseline: `f0e9d0d67422b0c286a2cb9e7d4e935a833a9533` (confirmed with `git rev-parse HEAD`). This is an implementation audit for the new system paper, not a reanalysis or validation of the older incident paper. All references below are relative to the repository root; `path:line` identifies the inspected baseline. Only this audit file was authored by this audit worker. No fresh platform requests, credential reads, private content output, or edits to collectors/raw captures were performed.

## Findings that constrain system-paper claims

1. **There is an implemented collection toolkit, but no demonstrated universal incident-configured collector.** Telegram has web preview, keyword/API, full-timeline API, comments, reaction refresh, and manifest-driven video acquisition. YouTube has discovery/metadata/comments and captions. TikTok has one-public-post comment pagination; Instagram has an authenticated hashtag collector plus a separate offline candidate-time decoder. Their interfaces, output shapes, and collection scopes differ. Numerous queries, dates, paths, domain lists, and lexical rules are incident specific. `IncidentSpec.platforms` accepting Facebook/Threads/X is a schema capability, not implementation of those collectors (`schemas/incident_spec.schema.json:38`; no native collector found by the source/test search recorded below).
2. **Implementation and validation must be reported separately.** The scoped offline regression command passed 97 tests. It exercises boundary rules, fixture pagination, typed reactions, integrity rejection, ledger/CLI behavior, and synthetic merges. It is not a live collector integration benchmark, platform coverage estimate, or semantic correctness assessment. Existing reports provide bounded historical receipts, not new validation performed in this audit.
3. **Technical provenance is strongest in the continuation merge and source-watch bridge.** They retain hashes, capture times, input paths/lines, and transformation identifiers. Neither a valid hash nor a typed ledger record proves a claim true, identifies the original source, or establishes independent corroboration. The bridge trusts collector-provided filtered article text after checking the referenced body bytes; it does not independently rederive that text from HTML (`src/analysis/source_ingest_bridge.py:215`).
4. **Missingness is heterogeneous.** Source Watch explicitly separates access failures, challenges, truncation, extraction fallback, and content changes. Telegram web collapses several first-page failures to `unavailable`, and the older YouTube collector can silently skip failed metadata extraction. A paper must not turn failed access, cursor exhaustion, missing captions, or absent API observations into evidence of absent content or events.
5. **Dependency setup is incomplete for the full toolkit.** The two checked-in requirement files cover contract validation and optional local ASR, not the complete ingestion/test stack. The documented quickstart installs only those files, while collectors import Telethon, yt-dlp, Instaloader, curl_cffi, BeautifulSoup, pandas, etc. (`README.md:123`; `requirements-contracts.txt:1`; `requirements-video-local.txt:1`). The existing shared virtual environment was sufficient for the scoped tests; plain system Python lacked pytest.
6. **Two existing report claims require qualification.** A TLS issuer-verification error is observed; the specific claim that missing Ukrainian state CAs in the local OS trust store caused a permanent failure is not established by the retained exception or collection code. Also, the lineage report's universal exact-offset rule is stronger than the ledger contract, which makes `Passage.locator` optional and checks it only for JSON representability (`src/evidence_ledger.py:344`).

## Provenance boundaries and missingness

### Technical provenance

The continuation merge is the clearest input-to-record chain: `read_snapshot` demands a finished manifest and required file hashes, verifies declared bytes before JSON decoding, records receipt hashes, and labels its own manifest digest as not independently signed (`src/analysis/build_continuation.py:50`–`:81`). Each observation receives raw kind/snapshot/path/line/fetch time, with inferred times identified (`:136`–`:151`). Multiple observations are retained in `sources`, even though only a ranked observation supplies the selected values (`:273`–`:278`). Output quality contains incomplete coverage, unfinished skipped inputs, alias changes, missing views/text, and album policy (`:326`–`:348`).

This does not mean all collection artifacts have equivalent provenance. Telegram web hashes only posts/channels JSONL in its manifest, not each stored HTML page (`src/tgweb_collect.py:233`); its raw JSONL lacks a page-file locator. Legacy prep does not check hashes (`src/analysis/prep.py:103`). YouTube comments have a collection-time fetch stamp but no raw HTTP body linkage (`src/youtube_collect.py:111`). Instagram comment rows lack an individual fetch timestamp (`src/instagram_collect.py:95`). The newer captions collector captures input and script hashes and hashes actual VTT bytes (`src/youtube_subtitles_collect.py:159`, `:198`). TikTok saves raw response body hashes and per-call metadata, but its normalized JSONL is referenced by path without a declared normalized-output SHA-256 in the manifest (`src/tiktok_public_collect.py:199`–`:213`).

The Source Watch bridge verifies raw body byte length and SHA-256 (`src/analysis/source_ingest_bridge.py:372`). The resulting Passage locator includes manifest hash, row index, body path/hash, source/capture URL, timestamp, extractor version, and a freshly computed text hash (`:231`). It does **not** check `extracted.content_sha256` against a separately trusted text value or rerun the extractor; its trust boundary includes the manifest's collector-provided text. A body integrity check protects bytes, not the correctness of text extraction or its relation to a claim. The legacy gzip bridge verifies decompressed bytes but creates no Passage (`:269`, `:289`).

The ledger enforces reference types and that a published ClaimMention comes from the claim's Source (`src/evidence_ledger.py:366`); this is valuable type/referential integrity, not proof of truthful attribution. Its `Passage.locator` is optional and any JSON value is accepted (`:344`). The lineage report's “every passage … exact character offsets or audio intervals” rule (`reports/provenance/corpus_and_sourcewatch_lineage_matrix_2026-11-09.md:176`) is therefore a reporting aspiration, not a global invariant enforced by the baseline.

### Semantic provenance

Forward metadata records the platform's attributed origin when exposed; deleted/private sources, screenshots, quotations, reuploads, editorial syndication, and translations may hide origin. Telegram web's forward label/name is not equivalent to an independently authenticated source chain (`src/tgweb_collect.py:90`). The source-lineage helper deliberately distinguishes confirmed explicit-reference edges, byte-identical media, candidate exact-text dependency, and unknown lineage (`src/analysis/source_lineage.py:54`). It does not turn disconnected nodes into independent sources. This should be presented as conservative dependency bookkeeping with manual/supplied relationship evidence, not automatic discovery of the first author or independent corroboration.

Collection policies also do not validate semantic coding. The preprocessing language heuristic counts Ukrainian/Russian distinctive letters (`src/analysis/prep.py:65`). Its relevance is incident date + village-name or place-and-topic regex (`:74`), and it strips repeated short lines as boilerplate (`:47`). These rules can lose meaningful repeated text or miss paraphrases; synthetic boundary tests do not quantify recall/precision on arbitrary incidents. The fixed UTC+2 `KYIV` timezone is explicitly November-2026-specific (`:17`), not a general Europe/Kyiv timezone implementation.

### HTTP/TLS and access missingness

Source Watch preserves status, final URL, content type, byte truncation, body hash and selected cache headers (`src/source_watch_collect.py:179`). It rejects non-HTTPS/non-allowlisted credential-bearing URLs (`:54`), same-source redirect violations (`:163`), oversized bodies, non-success status, unsupported type, and recognizable challenge titles (`:295`–`:305`). Errors are comparison state `error`, while first successful page is only `new_page` and extraction-version changes create a new baseline (`:185`). The last successful capture remains the comparison baseline through intervening failures (`:212`). Reports explicitly say access failure does not establish absent publication, and first baseline does not establish novelty (`:250`). These are defensible system behaviors.

Its total time budget is checked around redirects/body chunks; the code documents that an individual blocking read may exceed the nominal budget by up to the read timeout (`:140`). `trust_env=False` suppresses environment credentials/proxies/CA overrides (`:151`); standard certificate verification remains enabled. There is no `verify=False`, TLS bypass, or fallback to insecure HTTP in this collector. `run` catches requests/OSError/ValueError and records bounded exception text (`:306`). This is transport failure receipt handling; no certificate-chain diagnostics are performed.

The retained dedicated report contains two DBR `SSLCertVerificationError` failures (`reports/source-watch/20261108/latest.md:9`, `:17`). A later lineage report asserts missing Ukrainian government root/intermediate CAs in the local OS trust store (`reports/provenance/corpus_and_sourcewatch_lineage_matrix_2026-11-09.md:152`), and its builder repeats this as permanent root cause (`scripts/provenance/build_lineage_matrix.py:523`). The underlying error “unable to get local issuer certificate” does not identify which certificate was missing, where the chain was incomplete, whether the server chain or client CA bundle was responsible, or permanence. The system paper should say “certificate-chain verification failed in that execution environment; direct-source coverage was unavailable,” unless separate chain/certificate evidence is supplied. This audit made no network request to diagnose it.

Other collectors have weaker or different receipts: Telegram web catches requests exceptions and retries without serializing exception type; first-page failures collapse to `unavailable`, later failure to `page_error` (`src/tgweb_collect.py:39`, `:135`, `:154`). TikTok records HTTP/platform/parse state and stops subsequent live calls after an error (`src/tiktok_public_collect.py:126`–`:144`); `has_more=false` only confirms API pagination exhaustion (`:39`). Captions separate rate-limit/login/bot-block/unavailable/extraction-error and no-original-caption states (`src/youtube_subtitles_collect.py:100`, `:162`). YouTube metadata may disappear under `ignoreerrors` with no structured failure receipt (`src/youtube_collect.py:59`, `:95`). These states should not be collapsed into one universal “not found.”

## Dependencies, CLI shape, and reproducibility

At baseline there is no checked-in root `pyproject.toml`, unified requirements file, or ingestion lockfile. `requirements-contracts.txt` contains `jsonschema>=4.18.0,<5` and `referencing>=0.30`. `requirements-video-local.txt` pins faster-whisper 1.1.0, PyAV 18.1.0 and requests 2.34.2, with a PyAV compatibility explanation. These do not install the full collector stack or pytest. `pytest.ini:1` points pytest at `tests` and adds repository root to Python path; scripts mix `src.*`, bare module imports, and conditional relative imports (`src/analysis/build_continuation.py:20`, `src/tg_api_snapshot.py:17`).
