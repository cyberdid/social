# Master Plan closeout та інтеграція DR1–DR4 — 8 листопада 2026

## Вердикт

**Master Plan не завершено.** DR1–DR4 тепер наявні в проєкті й зіставлені з кодом. Частина роботи без зовнішніх експертів виконана: виправлено research register, перевірено MTProto reaction parity на 10 повідомленнях із трьох гілок, повністю технічно декодовано 607 унікальних Telegram-відео, створено п'ять точних `source_attributed` цитат плюс окрему контекстну цитату і один source-reported денний event mention. Жодне з цього не підтверджує фізичні обставини. Реальний кейс усе ще не має перевіреної фізичної хронології або незалежно валідованих NLP/video classifiers.

Чинна інтегрована версія: [Master Plan v1.1](../../docs/plans/social-master-plan-v1.1.md). Попередня v1.0 залишена як історичний документ і позначена superseded, бо помилково вказувала, що PDF DR1/DR3 не знайдені.

## 2. Що фактично закрито в цьому продовженні

1. **Виправлено research register.** Фінальні PDF DR1 і DR3 знайдено у відповідних Documents-каталогах, скопійовано без змін до `docs/research/`, хеші збігаються з оригіналами. Архівні DR1–DR7 від 5 листопада залишаються AR1–AR7 і не плутаються з поточними потоками.
2. **Оновлено чинний Master Plan до v1.1.** Він містить зіставлення DR1–DR4 із поточним кодом, case receipts і статусами. Виправлено застарілу v1.0; загальний статус лишено NOT COMPLETE.
3. **Перевірено MTProto reaction mapping.** 10 нових приватних snapshot rows збіглися за `reaction_state` і канонічним вектором `(kind,key,count)` з відповідями `messages.getMessagesReactions` для тих самих comment IDs. Зіставлення охопило три linked discussion threads і виконано без reactor lists. Агрегований звіт: [parity receipt](../audience-response/telegram-reaction-parity-2026-11-08.md); ідентифікатори й точні рядки лишилися поза Git у файлі з режимом `0600`.
4. **Завершено технічний full decode локального Telegram-архіву.** Усі 607 унікальних SHA-256 assets пройшли strict decode; усі розміри й хеші збіглися з archive input. Кожен asset має рівно один рядок у фінальному індексі. Зведення й hashes: [Telegram full decode](../video-pipeline/telegram-full-decode-2026-11-08.md). Сутність сцени, час, місце, мова, слова й зв'язок із подією цим не встановлено.
5. **Оновлено W10/W14 status і план.** Застаріле твердження про відсутність full decode прибрано; повторний parity-check відзначено виконаним лише в межах малого bounded sample.
6. **Аудит bounded case replay.** В архівованому historical run та повторному current-code run перевірено 8/8 входів і 16/16 виходів кожного відносно відповідних приватних маніфестів. Із 16 спільних виходів 5 ідентичні побайтно, 11 відрізняються. Content-free crosswalk зберігає всі хеші без сирих входів/медіа/абсолютних шляхів. Звіт: [case replay audit](../automated-case-run-2026-11-08/replay-audit-2026-11-08.md); release artifact inventory оновлено до 65 елементів із повторно звіреними байтовими хешами.

## 5. Що ще можна робити автономно без зовнішніх експертів

Наступні дії мають сенс без зовнішньої експертизи, але не повинні видаватися за independent gold:

1. Завершити збережений relevance sample як прозорий single-coder screening із зафіксованими неоднозначними випадками; recall лишається оцінкою конкретного кодера.
2. Продовжити вже почате: оцінити ще кілька вузьких `reported` claims про зміст конкретних першоджерел, із точними offsets та контрджерелами, де вони наявні; не перетворювати ці claims на твердження про фізичну істину. Один meta-claim про зміст сторінки МВС уже має окремий receipt.
3. Побудувати source-lineage candidate graph на 30 архівованих passages і зв'язати його з claims, лишаючи edge/root статус unknown без прямого цитатного доказу.
4. Формально скласти фізичну chronology як перелік attributed/unresolved event reports, окремо від publication chronology; не вважати повідомлення органів незалежним підтвердженням самих подій.
5. Для W14 local synthetic response-state contracts тепер перевірені; подальша live перевірка потрібна, щоб оцінити реальне API coverage/semantics на невеликому вибірковому наборі, без підвищення меж запитів і без reactor identities.
6. Для ASR взяти невелику стратифіковану reference вибірку й підготувати кандидати для звірки з оригінальним звуком. Без незалежно перевіреної розшифровки WER/CER та quote accuracy лишаються not evaluated.
7. Перевірити старі PDF-и та report manifests проти оновленого Markdown; жоден PDF не має містити superseded DR1/DR3 status.

## 6. Межа завершення

**Закрито:** research artifacts DR1–DR4 зведені; master plan виправлений; 10-row reaction parity pass; strict technical decode 607/607; один bounded source-to-text assessment, п'ять source-attributed цитат із п'яти сторінок плюс контекстна цитата, та один source-reported day-level event mention; W14 state-handling fix та 1.0→1.1 compatibility з TDD; transcript correction contract і source refs розмежовані; повний code suite 671 passed, 16 subtests passed.

**Не закрито:** source-backed findings про фізичні обставини, physical-event chronology, relevance recall, незалежні semantic gold labels, video transcript/scene validation, organic controls і повний semantic release evaluation. Один source-statement result не заповнює ці прогалини. Самі по собі додаткові програмні тести або AI-консенсус їх не закриють.
